# CI: pin the artifact-installing jobs to ubuntu-24.04 (#199)

Issue [#199](https://github.com/gregwebs/tiny-desk-splitter/issues/199) reports
`main` CI red on two external-install steps while every code-level gate passes.
The cause is not the repo's code: `ubuntu-latest` moved to **Ubuntu 26.04.1**,
and neither installer can cope with that image. The `rust` and `playwright` jobs
now pin `ubuntu-24.04`, and the Hurl install fails loudly instead of handing a
non-.deb to apt.

## Diagnosis

Job logs are unreachable from the authoring sandbox
(`results-receiver.actions.githubusercontent.com` does not resolve), so the
failures were reproduced on the runner image itself rather than read:

| Step | Exit | Reproduced error |
| --- | --- | --- |
| `rust` / `Install Hurl` | `100` | `The following packages have unmet dependencies: hurl : Depends: libxml2 but it is not installable` |
| `playwright` / `Install Chromium` | `1` | `BEWARE: your OS is not officially supported by Playwright; installing dependencies for ubuntu26.04-x64 as a fallback.` / `Cannot install dependencies for ubuntu26.04-x64 with Playwright 1.60.0!` / `Error: ERROR: Playwright does not support chromium on ubuntu26.04-x64` |

Both are consequences of the image, not of a flake:

- **Hurl.** `ubuntu-latest` is Ubuntu 26.04.1 (`PRETTY_NAME`), which packages
  libxml2 2.15 as **`libxml2-16`** and ships only `libxml2.so.16`: there is no
  `libxml2` package and no `libxml2t64` either, and the `.deb`'s other renamed
  dependency, `libcurl4`, is likewise gone in favour of `libcurl4t64`. The pinned
  hurl 8.0.1 `.deb` hardcodes `Depends: libc6 (>= 2.17), libcurl4, zlib1g,
  libxml2` (generated by hurl's `bin/release/create_deb_package.sh`, unchanged in
  8.1.0), so apt cannot satisfy it and exits 100. The release **tarball is not a
  way out**: its `bin/hurl` is dynamically linked against `libxml2.so.2`, so it
  exits 127 on 26.04. Every hurl release binary is therefore unusable there; only
  a source build against 26.04's libxml2 works (`cargo install hurl --version
  8.0.1 --locked` succeeds in ~60 s with the pinned toolchain).
- **Playwright.** `npx playwright install --with-deps chromium` has a per-OS
  package map (`nativeDeps.ts`) that, in 1.60.0, stops at `ubuntu24.04`. On an
  unrecognised OS it warns and then hard-fails instead of installing deps. The
  same probe with `@playwright/test@1.61.0`, whose map includes
  `ubuntu26.04-x64`, installs Chromium successfully.

`frontend` and `shellcheck` never broke: they install nothing from outside the
image, and every code-level gate in `rust` passed on 26.04.

## Change

- `rust` and `playwright` run on `ubuntu-24.04` instead of `ubuntu-latest`. Those
  are the two jobs that install third-party release artifacts, and both pins now
  have a known-good image. `frontend` and `shellcheck` stay on `ubuntu-latest`,
  so an image rollover still surfaces on every PR through the jobs that do not
  depend on an upstream package map.
- `Install Hurl` downloads with `-f` + `--retry 3 --retry-all-errors`,
  checks the `.deb` against the release's published `.sha256` (a mismatch fails
  the step), and prints `hurl --version`. Without `-f`, `curl --location
  --remote-name` writes an HTML error body to `hurl_8.0.1_amd64.deb` and exits 0,
  and apt then reports the whole thing as exit code 100 — the shape that made
  this issue's failure hard to place.
- A "Runner image" comment at the top of `ci.yml` records the two error strings,
  why the pins exist, and what re-pinning to `ubuntu-latest` requires.

## Why not the alternatives

- **Bump Playwright to 1.61 and keep `ubuntu-latest`.** It fixes only half the
  problem: the Hurl release binary has no 26.04-compatible form, so the `rust`
  job would need `cargo install hurl` (~60 s every run, plus a second place that
  owns `HURL_VERSION`) or a distro `hurl` (26.04 universe has 7.1.0, unpinned by
  the repo and older than the suite was written against). Both are larger
  changes than a two-line pin, and neither is needed to get the gates running.
  Bumping Playwright also moves the browser revision, which would have to be
  revalidated together with the e2e suite in the same change.
- **Install the 26.04 libraries and force the .deb in.** `dpkg -i --force-depends`
  would install it, but the binary still needs `libxml2.so.2`, which the image
  does not have.
- **Pin only `Install Hurl`'s step.** GitHub Actions pins images per job, not per
  step.
- **Retry or cache the Chromium download.** The issue suggests it, but the
  Chromium download was never the failing part: `--with-deps` exits before (and
  instead of) installing anything on an OS its package map does not list. Adding
  retries there would only make the same hard failure slower.

## Confirming the diagnosis

The probes above ran as a throwaway workflow on `ubuntu-latest`, reporting their
findings through check-run annotations (the one log surface reachable from the
sandbox) — image/`apt-cache` state, the current Hurl install (exit 100 plus apt's
dependency error), the release tarball for 8.0.1 and 8.1.0 (`ldd` plus exit 127),
the distro `hurl` candidate, `cargo install hurl --version 8.0.1 --locked`
(exit 0, ~60 s) and Playwright 1.60.0 vs 1.61.0 `install --with-deps chromium`.
That workflow was deleted before the PR; nothing in it is needed to reproduce the
result — each probe is a copy of a step in `ci.yml`, run on `ubuntu-latest`.

## Residual

The pins are a deliberate stopgap, not a permanent answer: `ubuntu-24.04` will
be retired eventually, and until then CI no longer builds on the newest LTS.
Retiring the pin needs Playwright ≥ 1.61 (whose `nativeDeps.ts` lists
`ubuntu26.04`) and an hurl install that resolves no apt package names: a source
build (`cargo install hurl --version 8.0.1 --locked`, ~60 s, verified to work on
26.04), or an upstream release built against that image's libxml2. The pinned,
checksum-verified release-tarball pattern the `cargo-nextest` install already uses
becomes available for hurl once its tarball links a libxml2 the image still
ships.
